# نسخة الويب — تطبيق الموظفين

**تطبيق الموظفين نفسه (`frontend/`) مبنياً للمتصفّح**: كل الشاشات، الخادم نفسه (`api.daaya.ly`)،
الحسابات والصلاحيات نفسها. لا شاشة كُتبت للويب وحده؛ الفروق القليلة مذكورة في §٣.

- **يملأ النافذة كاملةً**، والعناصر (الخطوط، الحشوة، الأيقونات) بأحجام الهاتف: كل شاشةٍ مرسومةٌ
  لهاتفٍ عرضه ٤٣٠، فيُقاس كلُّ `.w` و`.sp` على «جهازٍ» عرضه ٤٨٠ على الأكثر، والصفوف والبطاقات تمتدّ
  بعرض النافذة (`lib/core/widgets/web_frame.dart`).
- الشبكات (أرقام الرئيسية، حالات الطلبات، تصاميم العميل، صور المنتج) تزيد أعمدتها مع العرض، والصور
  المربّعة (معرض المنتج، QR، معاينة الكيس) لا تتجاوز ٥٦٠. على الهاتف كما هي — عمودان.
- **سرعة الفتح:** محرّك الرسم (`canvaskit.wasm`) يُنشر مع الصفحة لا من خوادم Google — جلبُه من
  gstatic أخذ ٤ ثوانٍ والتطبيق لا يبدأ قبله — وشاشة البداية بلا حدٍّ أدنى على الويب. من ٥٫٦ ثانية
  إلى الدخول صار ٠٫٨ على الماك.

> **النطاق المقترح في هذه الوثيقة `staff.daaya.ly`.** إن اختير غيره، يُستبدل حيث ورد.

---

## ١. الروابط

لكل شاشةٍ رابطها كما في `Routes` (`lib/core/router/app_router.dart`)، بلا `#`:

| الرابط | الشاشة |
|---|---|
| `/` · `/orders` · `/warehouse` · `/customers` | الأقسام الأربعة في الشريط السفلي |
| `/orders/52` · `/orders/52/payments` · `/orders/52/status` | طلبية، دفعاتها، تغيير حالتها |
| `/customers/730` · `/customers/730/designs` · `/customers/730/wallet` | عميل، تصاميمه، محفظته |
| `/products/1` · `/purchase-orders/1` · `/vendors/1` · `/shortages/1` | السجلّ الواحد |
| `/treasury` · `/payment-settlement` · `/reports/profit-loss` | الحسابات والتقارير |
| `/investment` · `/investors/1` · `/investor-deals/1` | الصندوق والمستثمرون |
| `/support/tickets/1` · `/internal-tickets/1` | المحادثات |
| `/tools/qr` · `/tools/bag-preview` | الأدوات |

**ما يحدث حين يُفتح رابطٌ مباشرةً، أو تُحدَّث الصفحة:**

1. يمرّ بشاشة البداية دائماً — هي من يسأل الخادم عن الجلسة ويملأ الصلاحيات.
2. **بلا جلسة:** إلى `/login?from=/orders/52`، وبعد الدخول إلى الرابط نفسه. `from` يُقبل مساراً
   داخلياً وحده؛ رابطٌ إلى خارج التطبيق يُرمى (`Routes.returnTarget`).
3. **بجلسة:** الرئيسية أولاً ثم الشاشة فوقها، فيظهر سهم الرجوع ويقود إلى الرئيسية. الأقسام الأربعة
   تُفتح كما هي (`AppRouter.openReturned`).
4. زرّا الرجوع والتقدّم في المتصفّح يعملان كسهم الرجوع. وما تحمله الشاشة من المكان الذي فُتحت منه
   (فلترٌ، طلبيةٌ مُمرَّرة) يبقى معها عند الرجوع إليها (`SessionExtraCodec`).
5. **بعد التحديث** تُبنى الشاشة كأنها رابطٌ جديد: ما كان يُمرَّر من الشاشة السابقة يُجلب من جديد.
   - روابط التعديل `/customers/:id/edit` و`/roles/:id/edit` و`/employees/:id/edit` تفتح صفحة السجلّ
     نفسه — لا نموذج «إضافة» فارغاً كان سيُنشئ سجلّاً ثانياً.
   - النماذج التي لا رقم في رابطها (`/vendors/form`، `/shipping-companies/form`، `/stock-items/form`…)
     تفتح بعد التحديث نموذجَ إضافة، وعنوانها يقول ذلك.

## ٢. ما جُرّب

على Google Chrome بلا واجهة، بالمتصفّح الحقيقي، مقابل نسخةٍ معزولة من الخادم على قاعدةٍ منسوخة
(لا بيانات حقيقية مُسّت)، وعلى بناء الإصدار نفسه الذي يُنشر:

- ١٠٨ مسارات فُتحت واحداً واحداً: لا خطأ JavaScript، وكلٌّ رُسم ورابطه في الشريط.
- الدخول من رابطٍ مباشر والعودة إليه، البقاء بعد التحديث، الخروج، كلمة مرورٍ خاطئة.
- التبويبات، فتح طلبية، الرجوع والتقدّم في المتصفّح، التحديث على شاشة تفاصيل.
- رفع تصميمٍ لعميل (من «مستندات» ومن «صور»)، تسجيل دفعةٍ بحوالةٍ مع واصل.
- تنزيل الفاتورة PDF (بالعربية، كما على الهاتف)، تنزيل تصميم، رمز QR، معاينة الكيس.
- ملاحظةٌ صوتية: تسجيلٌ وإرسال وتشغيل. الدعم الفني: ردٌّ نصّيّ ومرفقُ صورة. الخريطة.
- الحاسوب بعرض ١٤٤٠ والهاتف بعرض ٤٣٠: كلُّ المسارات في الحالين.

## ٣. ما يختلف عن الهاتف

| | الهاتف | الويب |
|---|---|---|
| إشعارات الدفع (FCM) | تعمل | **لا تعمل** — قسم «التنبيهات» مخفيّ في الإعدادات. الجرس داخل التطبيق يعمل. |
| «تحميل» و«مشاركة» | الصور / الملفات / ورقة المشاركة | **تنزيلٌ** إلى مجلّد التنزيلات باسم الملف. الزرّان «تنزيل الفاتورة» و«تنزيل المعاينة». |
| اختيار ملف | منتقي النظام والكاميرا | منتقي الملفات في المتصفّح (والكاميرا على متصفّح الهاتف). |
| الملاحظات الصوتية | AAC/m4a | AAC/m4a كالهاتف في Chrome وEdge وSafari. **Firefox لا يسجّل AAC** فلا يبدأ التسجيل فيه؛ الاستماع يعمل في الكل. |

الكود: `LocalFiles` (`lib/core/files/local_files.dart`) — الملف على الهاتف مسار، وعلى الويب رابط
blob، والرفع والحفظ والعرض يمرّ من هناك. و`shareFiles` ينزّل على الويب بدل ورقة المشاركة.

## ٤. البناء

```bash
cd frontend
./scripts/release_web.sh --build-only     # الناتج في build/web
```

يبني نكهة الإنتاج (`.env` → `https://api.daaya.ly/api/v1`) ويفحص الناتج نفسه: ملفّ البيئة المحزوم
يشير إلى `https`، و`index.html` فيه ما يزيل شاشة البداية.

> **`assets/.env` يُنشر مع الصفحة ويقرؤه أي زائر.** لا شيء فيه سرّي اليوم (عنوان الخادم، مفتاح
> Reverb العام). سطرٌ سرّي يُضاف إليه يوماً يصير عامّاً على الويب.

## ٥. النشر على خادم الإنتاج — مرةً واحدة

### ٥.١ النطاق

سجلّ `A` لـ`staff.daaya.ly` إلى عنوان `api.daaya.ly` نفسه.

### ٥.٢ nginx للنسخة

`/etc/nginx/sites-available/staff-web`، ثم ربطٌ في `sites-enabled` و`certbot --nginx -d staff.daaya.ly`:

```nginx
server {
    listen 80;
    server_name staff.daaya.ly;

    root /var/www/staff-web;
    index index.html;

    # كل مسارٍ ليس ملفاً مسارٌ في التطبيق: /orders/52 يُجاب بـindex.html.
    # بلا $uri/ — مجلّدٌ اسمه كاسم مسار كان سيُعرض بدل التطبيق.
    location / {
        try_files $uri /index.html;
    }

    # أسماء ملفات Flutter لا تتغيّر بين النسخ (main.dart.js …)، فلا تُحفظ في المتصفّح بلا سؤال:
    # يسأل كل مرة ويأخذ 304 إن لم يتغيّر شيء، وكل نشرٍ يصل في التحديث التالي.
    add_header Cache-Control "no-cache" always;

    gzip on;
    gzip_types application/javascript application/json application/wasm text/css image/svg+xml;

    # النسخة داخلية للموظفين.
    add_header X-Robots-Tag "noindex, nofollow" always;

    # محرّك الرسم: إن لم يعرف mime.types امتداد wasm أُرسل application/octet-stream، فيُفكّ أبطأ.
    location ~* \.wasm$ {
        default_type application/wasm;
        try_files $uri =404;
    }
}
```

`certbot` يضيف كتلة 443 ويحوّل 80 إليها.

### ٥.٣ CORS لصور الخادم — **ينتظر الموافقة**

الصفحة على `staff.daaya.ly` والصور على `api.daaya.ly`، والمتصفّح يرسم الصورة على Canvas فلا
يقبلها من نطاقٍ آخر إلا بترويسة `Access-Control-Allow-Origin`. الـAPI عليه الترويسة أصلاً
(`api/*`)؛ الصور لا. وهي نوعان، ولكلٍّ تعديل:

1. **الصور العامة** (المنتجات، الإعلانات) — ملفاتٌ ثابتة يقدّمها nginx بنفسه. في كتلة
   `api.daaya.ly` الموجودة:

   ```nginx
   location ^~ /storage/ {
       add_header Access-Control-Allow-Origin "*" always;
       try_files $uri /index.php?$query_string;
   }
   ```

   إن كانت في الكتلة قاعدةٌ للملفات الثابتة (`location ~* \.(jpg|png…)$`)، تُضاف الترويسة هناك أيضاً.

2. **الملفات الخاصة** (التصاميم، الواصلات، المرفقات) — روابط موقّعة يقدّمها Laravel من
   `storage/{path}`، والطلب يمرّ بـPHP فلا تصله ترويسة الكتلة أعلاه. تغييرٌ في `backend/`:
   ملفّ `config/cors.php` (نسخة الافتراضي) وفيه `'paths' => ['api/*', 'sanctum/csrf-cookie', 'storage/*']`.

جُرّب على النسخة المعزولة: بلا الترويسة تظهر التصاميم علامةَ «لا صورة» ويقول المتصفّح إن CORS
منعها، ومعها تظهر.

### ٥.٤ الرفع

`frontend/scripts/web_deploy.local.sh` (غير متتبَّع):

```bash
WEB_HOST=<اسم الخادم كما في ~/.ssh/config>
WEB_ROOT=/var/www/staff-web
```

ثم `./scripts/release_web.sh`. يرفع إلى مجلّدٍ جانبيّ ثم يبدّله دفعةً واحدة، ويُبقي السابق في
`/var/www/staff-web.prev` للرجوع إليه.
